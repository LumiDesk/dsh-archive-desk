# DSH 归档工作台（dsh-archive-desk）· 设计稿 v1

> 状态：待拍板（第 13 节）

## 0. 一句话

在侧边栏加一个「归档管理」入口，中间打开一张管理页：分页列出**所有已归档对话**（标题 + 内容摘要 + 项目 + 时间 + 体积），支持搜索、多选、全选、删除；删除默认进回收站（可恢复），也可一键切成彻底删除；同一套能力暴露成 Agent 工具。

---

## 1. 目标与非目标

### 目标

1. 把「归档」从死胡同变成完整闭环：**归档 → 查看 → 恢复 / 删除**。
2. 删除真落到磁盘（会话目录、投影缓存、workspace 引用），不是再挂一个标记。
3. 默认安全：回收站可恢复；彻底删除必须二次确认。
4. Agent 可调用：`archived_conversations` 工具与 UI 共用同一个 Host 服务方法。
5. 行为可解释：每一项都能说清「删了什么、留下什么、怎么恢复」。

### 非目标

- 不替代 DSH 自带的「归档」按钮（归档仍由核心负责）。
- 不做会话导出（已有 `dsh-session-log-export`，未来可加"删除前导出"）。
- 不清理 `~/.dsh/attachments`（内容寻址、多会话共享，删了会连累其他会话）。
- 不管理未归档会话（未归档的必须先归档，删除入口只认归档集合）。

### 1.1 与已有实现的关系（2026-10-20 扫描，未逐一验证）

同名或同类插件已经不少：`dsh-archive-manager` 这个名称至少被 6 个仓库占用（列表、恢复、永久删除各有实现），
`dsh-recycle-bin`、`dsh-conversation-recycle-bin` 已经覆盖「软删除 + 回收站」，生态里甚至已经有
「归档面板居中弹窗」的形态。所以本项目的差异必须收窄到两条：

1. **Agent 可调用**：现有实现都只面向人手点，没有为 Agent 设计工具契约；
2. **事务安全**：先文件后状态、失败可回滚、悬空引用可治理、运行中会话硬拦截。

如果最终只做出「列表 + 删除」，那它就是第 7 个重复品。这也是为什么 Agent 工具不是可选项，
而是这个项目存在的理由。

## 2. 产品形态

### 2.1 入口：侧边栏图标 → 中间整页

DSH 原生的「侧栏图标 + 中间面板」机制，和**自动化任务**完全同构：

| 位置       | 槽位                | 说明                                       |
| ---------- | ------------------- | ------------------------------------------ |
| 侧栏图标列 | `sidebar.panellist` | 和「自动化任务」同一列，`order` 排在它后面 |
| 中间主面板 | `main`（keyed）     | key 与侧栏图标 id 相同：`archive-desk`     |

点击图标 → `ctx.layout.selectPanel('archive-desk')` → 中间区域从对话切换到管理页（不是浮层）。

### 2.2 为什么是整页而不是浮层弹窗

你说的"中间弹出来一个弹窗"，在 DSH 的形态里对应的其实就是**中间整页面板**——「插件」页、「自动化任务」页都是这个形态。理由：

1. **空间**：列表 + 分页 + 多选 + 回收站，浮层里做会挤，整页和「插件」页一样宽裕。
2. **一致性**：侧栏图标选中态、快捷键、面板切换、离开对话的返回路径，全是宿主管好的。
3. **不打断**：删除是长任务（几十个会话、几百 MB），整页可以稳定显示进度，浮层容易被误关。
4. **仍然有弹窗**：删除确认、清空回收站确认，用真正的模态对话框（`shell.overlay` 之上再叠一层，或页内 Modal）。

如果你坚持要浮层，内容组件可以复用，只是外面套一层 `shell.overlay`；但我不建议，理由如上。

### 2.3 页面结构

```
┌ 侧栏 ─────┬──────────────────────────────────────────────────────────────┐
│  ＋ 新对话 │  归档管理                                    6 个 · 2.4 MB    │
│           │                                                              │
│  项目 A    │  [ 已归档 6 ]  [ 回收站 2 ]                                   │

│           │  ☑  论文提纲               把 arxiv 那篇的提纲整理成… 项目B 昨天 44KB│
```

## 3. 交互细节

### 3.1 列表行

| 列     | 内容                      | 说明                                                          |
| ------ | ------------------------- | ------------------------------------------------------------- |
| 复选框 | 多选                      | 表头复选框 = 全选当前筛选结果                                 |
| 标题   | 会话标题                  | 取自日志里的 `session/title` 事件；无则用首条用户消息前 24 字 |
| 摘要   | 首条用户消息，最多 160 字 | 单行省略，悬停显示全文 tooltip                                |
| 项目   | workspace 标题 · 相对时间 | 悬停显示完整 cwd                                              |
| 体积   | 会话目录总字节            | 人类可读（KB/MB/GB）                                          |
| 状态   | `运行中` / `失效` 徽标    | 运行中不可删；失效只能"移除引用"                              |

行高 32px，和「插件」页列表一致；失败/缺失行用警告色 token，不用自定义颜色。

### 3.2 分页与搜索

- 默认按**最近活动时间倒序**；可选「按体积倒序」「按归档时间倒序」（归档时间只能近似为归档集合的顺序）。
- 每页 20，可切 10 / 20 / 50；页码 + 上一页/下一页。
- 搜索是 Host 侧做（因为摘要只在 Host 侧有），输入防抖 250ms。
- 搜索命中范围：标题、摘要、项目名、cwd、会话 id 片段。
- 分页是 offset 分页，删除后重新拉当前页并校正 offset。

### 3.3 多选与全选

- 选中集合只存在于 Client；跨页保留。
- 「全选」= 选中**当前筛选结果的全部**（不只是当前页），按钮文案显示数量："全选（共 47 项）"。
- 顶部显示"已选 12 项 · 36.4 MB"。
- 删除后选中集合里被删掉的 id 自动剔除。

### 3.4 删除确认弹窗（含回收站开关）

工具栏上一个常驻开关：

```
删除时放入回收站  [●——]     ← 默认开；关掉即"彻底删除"模式
```

点「删除所选」→ 模态：

```
┌ 删除 2 个归档对话？ ────────────────────────────────┐
│                                                     │
│  论文提纲                        44.2 KB            │
│  归档清理脚本                     8.1 KB            │
│  …另有 0 个                                        │
│                                                     │
│  释放空间：52.3 KB                                  │
│                                                     │
│  ○ 放入回收站（可随时恢复）  ●                      │
│  ○ 彻底删除（不可恢复）                             │
│                                                     │
│  [ ] 我已知晓：彻底删除后无法找回                     │
│                                                     │
│                              [取消]  [删除]         │
└─────────────────────────────────────────────────────┘
```

规则：

- 开关状态持久化，下次打开还是上次的选择。
- 弹窗里的单选可临时覆盖开关；确认后**不**反向修改全局开关（避免误改默认值）。
- 选「彻底删除」时必须勾选知情项，否则按钮禁用。
- 数量 > 20 时只列前 5 个 + "另有 N 个"。
- 弹窗内显示"其中 1 个正在运行，将被跳过"这类预检结果。
- 删除中：按钮转进度态，禁止重复提交；完成后 toast（成功 N / 失败 M + 原因）。

### 3.5 回收站 Tab

- 行：复选框、标题、摘要、删除时间、体积、来源项目。
- 单行操作：`恢复`、`彻底删除`。
- 顶部操作：`清空回收站`（二次确认，显示总释放空间）。
- 回收站条目在删除时就固化标题/摘要/cwd/体积，**不再依赖已删除的会话日志**（否则恢复列表还要解压日志）。

### 3.6 空态与异常态

| 场景                               | 显示                                                         |
| ---------------------------------- | ------------------------------------------------------------ |
| 没有归档对话                       | 插画 + "还没有归档的对话。在侧栏会话的「…」菜单里点归档。"   |
| 回收站空                           | "回收站是空的"                                               |
| 有失效引用                         | 顶部黄色提示条："发现 2 条指向已不存在会话的归档记录 [清理]" |
| Host 不可用（未挂载 sessionQuery） | 列表仍可显示 id，摘要显示"无法读取预览"；删除功能不受影响    |
| 插件被禁用                         | 侧栏图标消失，页面自动回退到对话                             |

## 4. 技术架构

### 4.1 组件划分

```
dsh-archive-desk/
├── package.json          # dsh.bundle.patch + dsh.client
├── cordis.patch.yml      # 插入 Host 行
├── index.js              # Host：服务 + RPC 通道 + 工具 + 事件监听
├── lib/
│   ├── store.js          # 磁盘操作：扫描、移动、删除、meta
│   ├── service.js        # ArchiveManagerService（业务方法）
│   ├── tool.js           # archived_conversations 工具定义
│   └── paths.js          # 路径解析与版本校验
├── client.js             # Client：槽位注册 + 页面
├── locale/{zh,en}.json
└── icon.svg
```

### 4.2 Host / Client 通信：原生 RPC 通道

不用手写 HTTP 路由，DSH 有现成的 Connection RPC 通道（`dsh-client-connection`）：

```js
// Host（在 apply 内，随插件 dispose 自动注销）
ctx.connection.rpc.handle('/archive-desk', async (endpoint, payload, signal) => {
  return service[endpoint](payload, signal) // list / delete / restore / purge / ...
})

// Client
const result = await ctx.connection.rpc.call('/archive-desk', 'list', {
  scope: 'archived',
  offset: 0,
  limit: 20,
})
```

- 通道自带鉴权（`connection.admit`）、JSON 信封、错误码、取消信号。
- 通道名 `/archive-desk` 合法（`^\/[A-Za-z0-9._~-]+$`）。
- 不需要 Typert 代码生成，不需要自己处理 cookie/token。

### 4.3 Host 服务方法（UI 与 Agent 共用）

| 方法                          | 入参                                                        | 返回                                          |
| ----------------------------- | ----------------------------------------------------------- | --------------------------------------------- |
| `list`                        | `{scope:'archived'\|'trash', offset, limit, query?, sort?}` | `{total, offset, limit, totalBytes, items[]}` |
| `delete`                      | `{ids[], mode:'trash'\|'purge'}`                            | `{deleted[], skipped[], freedBytes}`          |
| `restore`                     | `{trashIds[]}`                                              | `{restored[], failed[]}`                      |
| `purgeTrash`                  | `{trashIds[]}`                                              | `{purged[], freedBytes}`                      |
| `emptyTrash`                  | `{}`                                                        | `{purged, freedBytes}`                        |
| `cleanDangling`               | `{}`                                                        | `{removed[]}`（只清引用，不动文件）           |
| `getSettings` / `setSettings` | `{defaultMode, pageSize}`                                   | 同左                                          |

服务本身注册为 Cordis Service（`ctx.archiveManager`），这样工具、RPC、未来的命令都调同一份实现。

## 5. 磁盘契约与数据模型

### 5.1 会话本体（只读定位，不猜布局）

```
%USERPROFILE%\.dsh\
├── sessions\
│   └── <cwd 编码目录>\            # 例：--D-Projects-TestSpace--
│       └── session-<uuid>\        # ← 目录名带 session- 前缀
│           └── session.v4.jsonl.zstd
├── storages\
│   ├── workspace.json             # global.archivedSessionIds / workspaces[].sessionIds
│   └── session_projcache\sessions\
│       └── session-<uuid>.json    # 投影缓存（派生数据）
└── attachments\                   # 内容寻址，禁止触碰
```

定位方式：在 `sessions\*\session-<id>` 里找**目录**，不依赖文件名（`session.v4.jsonl.zstd` 版本号会变）。找不到目录 = 失效引用。

### 5.2 插件自己的数据

```
%USERPROFILE%\.dsh\archive-desk\
├── settings.json                  # { defaultMode, pageSize, ... }
└── trash\
    └── <trashId>\                 # 20261020T132501-<uuid>
        ├── meta.json
        └── payload\               # 被移动过来的整个 session-<uuid> 目录
```

`meta.json`：

```json
{
  "schema": 1,
  "phase": "moving | ready",
  "trashId": "20261020T132501-session-…",
  "sessionId": "session-…",
  "title": "论文提纲",
  "snippet": "把 arxiv 那篇的提纲整理成…",
  "cwd": "D:\\Projects\\TestSpace",
  "workspaceId": "…",
  "workspaceTitle": "TestSpace",
  "originalPath": "C:\\Users\\Administrator\\.dsh\\sessions\\--D-Projects-TestSpace--\\session-…",
  "movedAt": "2026-10-20T13:25:01+08:00",
  "sizeBytes": 45214,
  "detachedFromWorkspace": true,
  "wasArchived": true
}
```

不建全局索引文件：列表时扫 `trash/*/meta.json`（条目量小），避免"索引和实际不一致"这类经典故障。

### 5.3 状态来源

| 事实                 | 唯一来源                                   |
| -------------------- | ------------------------------------------ |
| 哪些会话被归档       | `ctx.workspaceRegistry.archivedSessionIds` |
| 会话在哪个项目里     | `workspaceRegistry.list()[].sessionIds`    |
| 标题、摘要、活动时间 | 会话日志（经 `ctx.sessionQuery`）          |
| 体积                 | 磁盘                                       |
| 回收站内容           | `trash/*/meta.json`                        |

**写操作一律走注册表 API**（`unarchiveSession` / `archiveSession` / `detachSession` / `attachSession`），绝不直接改 `workspace.json`——Host 内存里有状态，直接改会在某个时刻被覆盖回去。

## 6. 删除事务

### 6.1 前置校验（逐项）

1. `id` 在 `archivedSessionIds` 里（不在则拒绝，防止误删普通会话）。
2. 不在运行：`ctx.agents.get(id) === undefined && ctx.sessions.get(id) === undefined`。
3. 不在进行中的删除队列里（`inFlight` Set）。
4. 形如 `session-<uuid>`（防路径注入）。
5. 目录解析结果必须在 `sessions\` 前缀内（再次防越界）。

任何一项不通过 → 该项 `skipped`，带原因，其余项照常执行。

### 6.2 回收站模式（默认）

```
1. 写 trash/<id>/meta.json（phase=moving，原子写：tmp + rename）
2. rename(会话目录 → trash/<id>/payload)        # 同盘，原子
3. 更新 meta（phase=ready）
4. 删除投影缓存文件（尽力而为）
5. workspace.detachSession(id)（尽力而为）
6. workspaceRegistry.unarchiveSession(id)
7. ctx.emit('api-session/removed', id)           # 侧栏立刻消失
```

顺序原则：**先动文件，后动状态**。文件移动失败 = 什么都没变；状态写失败 = 只剩一个指向不存在会话的归档引用（隐形、无害、下次可清）。

### 6.3 彻底删除模式

```
1. rm -rf 会话目录
2. 删除投影缓存文件
3. detachSession / unarchiveSession / emit removed
```

无回收站条目，不可恢复。

### 6.4 失败与回滚

| 失败点            | 处理                                                                      |
| ----------------- | ------------------------------------------------------------------------- |
| meta 写失败       | 中止该项，目录未动                                                        |
| rename 失败       | 若已移走则移回，报告错误                                                  |
| 步骤 4-7 任一失败 | 文件已删/已移，标记 `partial`，返回警告；状态补偿可在"清理失效引用"里重试 |
| 整批中某项异常    | 不中断整批，逐项返回结果                                                  |

批处理串行执行（删除是 IO 密集但量小），每项之间 `yield` 一次，避免卡住事件循环。

### 6.5 恢复

```
1. 读 meta，phase 必须是 ready，payload 存在
2. 确保原父目录存在；rename(payload → originalPath)；目标已存在则报错
3. workspace.attachSession(id)     # 尽力而为；cwd 已不存在时会失败，降级为"未分组"
4. workspaceRegistry.archiveSession(id)   # 恢复到归档状态
5. 删除 trash 条目
```

恢复后立即回到"已归档"列表；侧栏里要等下一次会话列表刷新才出现（见 §10 限制）。

### 6.6 崩溃恢复

插件激活时扫 `trash/*/meta.json`：

- `phase=moving` 且 `payload` 存在 → 补写成 `ready`
- `phase=moving` 且 `payload` 不存在 → 整个条目清掉
- `ready` 但 `payload` 缺失 → 标记坏条目，列表里显示"损坏"并允许删除条目

## 7. Agent 工具

### 7.1 契约

工具名 `archived_conversations`，一个 `action` 参数，与 UI 共用 Host 服务：

```jsonc
{
  "action": "list | delete | restore | purge | empty_trash | stats",
  "scope": "archived | trash", // list 时用，默认 archived
  "ids": ["session-…"], // delete 用会话 id；restore/purge 用 trashId
  "mode": "trash | purge", // delete 时用，默认取插件配置
  "query": "登录", // list 过滤
  "offset": 0,
  "limit": 20,
  "confirm": false, // 破坏性操作为 true 才执行
}
```

规则：

- `delete` 必须 `confirm: true` 且 `ids` 非空，单次最多 100 个；**不提供 "all" 快捷方式**（避免一句话清空）。
- 只能删归档集合里的会话；运行中的直接跳过并说明。
- `mode: "purge"`、`purge`、`empty_trash` 默认对 Agent **关闭**（配置项 `agent.allowPurge=false`），被拒时返回可读原因 + "请在归档管理页操作"。
- 返回**结构化摘要**而不是原始列表：`{ok, deleted: n, skipped: [{id, reason}], freedBytes}`，列表类操作返回精简条目（id/标题/时间/体积/状态），不带全文。

### 7.2 权限与审批

- 可恢复的操作（trash 模式删除、restore）：不需要审批，Agent 可直接做。
- 不可恢复的操作（purge / empty_trash）：注册 `tools/pre-execute` 监听，对本工具返回 `ask`，走宿主审批弹窗；宿主没有审批通道时按框架默认拒绝。
- 配置可关：`agent.requireApprovalForPurge`（默认 `true`）。
- 这样"让 agent 能整理归档"和"不能一句话抹掉历史"两个目标同时成立。

## 10. 兼容性、安全与已知限制

### 依赖的内部面（按风险排序）

| 依赖                                   | 风险                       | 缓解                                                                           |
| -------------------------------------- | -------------------------- | ------------------------------------------------------------------------------ |
| `sessions\<shard>\session-<id>\` 布局  | 中：升级可能改             | 只按目录名 `session-<id>` 找，不碰文件名；找不到就报 `not-found`，不猜         |
| `workspace.json` 存储域                | 低：用注册表 API，不碰文件 | 只调 `unarchiveSession` / `archiveSession` / `detachSession` / `attachSession` |
| `session_projcache\sessions\<id>.json` | 低：派生数据               | 删不掉也无害，缓存会按日志指纹失效                                             |
| `sessionQuery.load()`                  | 中：服务可选               | 未挂载时降级：无摘要、标题用 id；删除不受影响                                  |
| `api-session/removed` 事件             | 低：已声明                 | 没有它只是"需要刷新页面"，不影响正确性                                         |

**版本护栏**：激活时探测上述能力，缺任何一个就把破坏性操作置为不可用并给出明确提示（`archive/unsupported`），而不是半残运行。

### 安全

- 只允许操作归档集合内的会话 id；路径解析后必须落在 `~/.dsh/sessions/` 内。
- 不跟随 junction / symlink（Windows 上 `stat` 前先 `lstat`，拒绝 `isSymbolicLink()`）。
- 删除是串行队列，同 id 幂等。
- RPC 通道走宿主的连接鉴权，不额外开 HTTP 路由。

### 已知限制（要在 README 和 UI 里写清）

1. 恢复后侧栏行不会立刻出现（要等会话列表刷新或重启）；管理页里立刻可见。
2. 附件不删：删除会话后 `attachments` 里可能有孤儿文件，这是刻意行为（共享安全）。
3. 只删"归档"会话；未归档会话必须先归档。
4. 回收站是全局的（跨项目、跨 profile 的 `~/.dsh`），不跟随项目。
