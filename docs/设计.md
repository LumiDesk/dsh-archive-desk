# DSH 归档工作台（dsh-archive-desk）· 设计

> 项目：<https://github.com/LumiDesk/dsh-archive-desk>

本文描述这个插件是什么、怎么实现、边界在哪，是设计与取舍的唯一出处。

---

## 0. 一句话

在侧边栏加一个「归档管理」入口，中间打开一张管理页：列出**所有已归档对话**（标题 + 摘要 + 项目 + 时间 + 体积 + 状态），支持搜索、排序、分页、多选、批量删除、回收站与恢复；删除默认进回收站，彻底删除必须显式选择并二次确认。同一套能力通过 `archived_conversations` 工具开放给 Agent，但 Agent 永远不能彻底删除。

---

## 1. 目标与非目标

### 目标

1. 把「归档」从死胡同变成完整闭环：**归档 → 查看 → 恢复 / 删除**。
2. 删除真落到磁盘（会话目录、投影缓存、workspace 引用），不是再挂一个标记。
3. 默认安全：回收站可恢复；彻底删除必须显式选择 + 知情勾选。
4. Agent 可调用：工具与 UI 共用同一个 Host 服务方法。
5. 行为可解释：每一项都能说清「删了什么、留下什么、怎么恢复、为什么跳过」。
6. 列表要快：归档量大时不做「每次请求重读所有日志」。

### 非目标

- 不替代 DSH 自带的「归档」按钮（归档仍由核心负责）。
- 不做会话导出（导出是 `dsh-session-log-export` 的事）。
- 不清理 `~/.dsh/attachments`（内容寻址、多会话共享，删了会连累其他会话）。
- 不管理未归档会话（未归档的必须先归档，删除入口只认归档集合）。
- 不做插件级配置。这个工具的行为由安全默认值决定，不提供部署旋钮（见 §8）。

## 2. 产品形态

### 2.1 入口：侧栏图标 → 中间整页

DSH 原生的「侧栏图标 + 中间面板」机制，和「自动化任务」同构：

| 位置       | 槽位                | 说明                                   |
| ---------- | ------------------- | -------------------------------------- |
| 侧栏图标列 | `sidebar.panellist` | `order` 排在自动化任务之后             |
| 中间主面板 | `main`（keyed）     | key 与侧栏图标 id 相同：`archive-desk` |

点击图标 → `ctx.layout.selectPanel('archive-desk')` → 中间区域切换到管理页。

### 2.2 为什么是整页

列表 + 分页 + 多选 + 回收站需要横向空间；整页还能复用宿主管好的侧栏选中态、快捷键和返回路径。只有删除/清空确认使用模态对话框。

### 2.3 页面结构

## 3. 交互细节

### 3.1 列表行与状态

| 列     | 内容                          | 说明                                      |
| ------ | ----------------------------- | ----------------------------------------- |
| 复选框 | 多选                          | 运行中行禁用；失效行可选                  |
| 标题   | 日志里的 `session/title`      | 无标题时用首条用户消息前 24 字，再退回 id |
| 摘要   | 首条用户消息，最多 160 字     | 单行省略，悬停显示全文                    |
| 项目   | workspace 标题 · 最近活动时间 | 悬停显示完整 cwd                          |
| 体积   | 会话目录总字节                | 人类可读（B/KB/MB/GB）                    |
| 状态   | 运行中 / 失效                 | 状态点或 Tag；悬停解释删除时会怎样处理    |

状态判定（关键）：

| 状态      | 条件                                      | 能否删除               |
| --------- | ----------------------------------------- | ---------------------- |
| `running` | `workspace/session-activity` 返回非空     | 能，先停止这些工作再删 |
| `ok`      | 目录存在、宿主没有任何活动                | 是                     |
| `missing` | 归档 id 存在，但 `sessions/` 下找不到目录 | 只能移除归档引用       |

状态只有一个来源：宿主的 `workspace/session-activity` 瀑布。它聚合 turn、job、定时任务与子 Agent，和 DSH 自己的归档准入用的是同一判定。

`ctx.sessions.get(id)` / `ctx.agents.get(id)` 表示会话已加载进宿主进程内存，既不等于「用户还开着」，也不等于「正在运行」：这个注册表是进程级的，启动后看过的会话会一直留着，归档本身也不卸载会话。所以「加载在内存」不是状态、也不是删除门槛，只是删除前要清理的宿主内部状态（§6.2 第 0 步）。

面板里只有 `ok` / `missing` 行可以勾选，`running` 行不参与批量选择，避免把正在跑的会话一起勾走。要删运行中的会话，走它的「…」菜单或 Agent 工具——两条路径都会先停掉它的工作再删（§6.2 第 0 步）。

### 3.2 搜索、排序与分页

- 搜索命中标题、摘要、项目名、cwd、会话 id 片段；Host 侧过滤，输入防抖 250ms。
- 排序是可见控件：最近活动（默认）、体积从大到小、标题、归档顺序。
- 每页 10 / 20 / 50，默认 20；不写 `localStorage`、不写服务端，刷新回到默认。
- 分页是 offset 分页；删除后按新总数校正页码，避免停在空页。
- 失效引用永远排在可读会话之后。

### 3.3 多选与全选

- 选中集合存在于 Client，跨页保留。
- 表头复选框选中**当前页可删除行**；部分选中时显示 indeterminate。
- 顶部显示「已选 N 项 · 体积」；体积只在所有选中项元数据已知时显示。
- 当筛选结果还有未选中项时，提供「选择全部 N 项」；`matchingIds` 有 1000 条上限，超出时明确提示。
- 切换 Tab、搜索词、排序、每页条数时清空选中，避免删除当前筛选下看不见的会话。
- 删除确认弹窗用 `inspect` 重新取选中项的标题、体积、状态，跨页数据也准确。

### 3.3.1 取消归档

- 已归档行有行内「取消归档」按钮；选中多行后工具栏也有批量「取消归档」。
- 只改注册表的 `archivedSessionIds`：不移动/删除文件，不改 workspace 归属。
- 目录已失效（`missing`）的行不提供取消归档，只能用「移除引用」清理。
- 运行中的会话允许取消归档（这不是破坏性操作）；侧栏行会通过 workspace 状态流回到原项目。
- 成功 Toast：「已取消归档 N 个会话」。

### 3.4 删除确认弹窗

删除模式在每次删除的确认弹窗里选择，没有全局开关：

```
┌ 删除 2 个归档对话？ ────────────────────────────────┐
│  所选会话会从归档列表移除；默认放入回收站，可恢复。   │
│  ┌──────────────────────────────────────────────┐  │
│  │ 论文提纲                              44.2 KB │  │
│  │ 归档清理脚本                           8.1 KB │  │
│  └──────────────────────────────────────────────┘  │
│  合计                              释放空间：52.3 KB │
│                                                     │
│  ● 放入回收站（推荐）   可在回收站里恢复              │
│  ○ 彻底删除             直接删除文件，不能恢复        │
│  [ ] 我已知晓：彻底删除后无法找回                     │
│                                                     │
│                              [取消]  [确认]         │
└─────────────────────────────────────────────────────┘
```

规则：

- 默认选中「放入回收站」；彻底删除必须由用户主动切换。
- 彻底删除时确认按钮置灰，直到勾选知情项。
- 弹窗先调 `inspect` 预检，显示「其中 N 个正在运行，删除前会先停止其工作」与「N 个仍有工作停不下来，将被跳过」和「N 个已不在归档集合」。
- 加载在宿主内存里的会话照常按事务删除：删除前先停掉它残留的工作（§6.2 第 0 步）。
- 数量 > 5 时只列前 5 个 +「另有 N 个」。
- 提交中按钮转 spinner 并锁定；ESC/遮罩关闭被忽略。
- 成功后 Toast：「已删除 N 个会话，释放 X」；有 partial/skipped 时追加说明。

### 3.5 回收站 Tab

- 行：复选框、标题、摘要、项目、删除时间、体积、状态、操作。
- 单行操作：`恢复`、`彻底删除`。
- 批量操作：恢复所选、彻底删除所选、清空回收站。
- 分页与归档 Tab 共用每页条数。
- 条目永久保留，清理由「清空回收站」或单条彻底删除完成。
- 损坏条目（缺 meta 或 payload）仍然显示，标「损坏」，只允许彻底删除。
- 回收站条目在删除时固化标题/摘要/cwd/体积，不依赖已删除的会话日志。

### 3.6 加载、空态与异常态

| 场景         | 显示                                                  |
| ------------ | ----------------------------------------------------- |
| 首次加载     | 6 行骨架屏 + `aria-busy`，不显示空白页                |
| 刷新/翻页    | 保留旧数据，列表降透明度 + 顶部小 spinner             |
| 没有归档对话 | 图标 +「还没有归档的对话」+ 归档入口说明              |
| 搜索无结果   | 图标 +「没有匹配的会话」+ 清空搜索按钮                |
| 回收站空     | 图标 +「回收站是空的」                                |
| 有失效引用   | 顶部黄色提示条：「发现 N 条失效引用」+ 清理按钮       |
| 加载失败     | 页内红色 banner + 重试；旧数据保留                    |
| Host 不可用  | 列表仍可显示 id；破坏性操作返回 `archive/unsupported` |
| 插件被禁用   | 侧栏图标消失，页面回退到对话                          |

### 3.7 无障碍与主题

- 弹窗使用宿主 `Modal`：焦点管理、ESC、遮罩点击、`aria-modal` 由宿主保证。
- 所有图标按钮有 `aria-label`；状态有可读文本，不只靠颜色。
- 颜色全部走 DSH 主题 token，自动适配浅色/深色。
- 支持 `prefers-reduced-motion`：关闭 shimmer/spinner 动画。

### 4.1 组件划分

```

│   ├── diagnostics.ts    # 启动诊断（last-boot.json）

├── locale/{zh,en}.json   # 插件目录元数据
└── icon.svg
```

### 4.2 Host / Client 通信

插件自注册一条前缀路由：

- 只接受 `POST /archive-desk/<endpoint>`；其余 405。
- 每个请求先 `connection.requestRejection(req)` 鉴权。
- 请求体上限 64 KiB；成功 `{ok:true,value}`，失败 `{ok:false,error:{code,message}}`。
- 不用 `connection.rpc.handle()`：它经 Connection 服务自己的 context 注册，在组合 profile 里读不到 `webServer`，第一次调用就会失败。

### 4.3 Host 服务方法（UI 与 Agent 共用）

| 方法            | 入参                            | 返回                                                                                            |
| --------------- | ------------------------------- | ----------------------------------------------------------------------------------------------- |
| `list`          | `{offset,limit,query?,sort?}`   | `{total,offset,limit,totalBytes,missing,missingTotal,matchingIds,matchingIdsTruncated,items[]}` |
| `inspect`       | `{ids[]}`                       | `{items[],total,totalBytes,deletable,running,notSettled,missing,notArchived[]}`                 |
| `unarchive`     | `{ids[]}`                       | `{unarchived[],skipped[]}`                                                                      |
| `delete`        | `{ids[],mode:'trash'\|'purge'}` | `{deleted[],partial[],skipped[],freedBytes}`                                                    |
| `restore`       | `{trashIds[]}`                  | `{restored[],failed[]}`                                                                         |
| `purgeTrash`    | `{trashIds[]}`                  | `{purged[],failed[],freedBytes}`                                                                |
| `emptyTrash`    | `{}`                            | 同 `purgeTrash`                                                                                 |
| `listTrash`     | `{offset,limit}`                | `{total,totalBytes,offset,limit,items[]}`（含损坏条目）                                         |
| `cleanDangling` | `{}`                            | `{removed[],failed[]}`                                                                          |

服务实例按 plugin context 记忆化：HTTP 路由与 Agent 工具共享同一个实例，`busy` 集合和摘要缓存因此在全部请求之间生效，同一会话不会被两个请求同时处理。

### 4.4 Client 注册点

- `sidebar.panellist`：`id: archive-desk`，自定义归档图标。
- `main`：`key: archive-desk`，注入 `t`。
- `sidebar.workspaces.session.menu.item`：仅已归档会话可见的「删除」，点击后打开面板并复用同一个确认弹窗。

Client 使用 `@deepseek-ai/dsh-client-ui-primitives`（DSH 页面自带的平台 seed 模块），通过 `dsh.client.external` 声明、esbuild external，不打包第二份 React/组件。

## 5. 磁盘契约与数据模型

### 5.1 会话本体（只读定位）

```
%USERPROFILE%\.dsh\
├── sessions\
│   └── <cwd 编码目录>\
│       └── session-<uuid>\
│           └── session.v4.jsonl.zstd
├── storages\
│   ├── workspace.json             # global.archivedSessionIds / workspaces[].sessionIds
│   └── session_projcache\sessions\
│       └── session-<uuid>.json    # 投影缓存（派生数据）
└── attachments\                   # 内容寻址，禁止触碰
```

- 只按目录名 `session-<uuid>` 定位，不依赖日志文件名（文件名里的格式版本会变）。
- `locateSession` 检查 shard 和 session 目录都**不是 symlink/junction**，防止越界。
- 列表用 `scanSessionIndex` 一次扫描 `sessions/*` 建索引，成本随会话目录数增长，而不是随「归档 id × shard」增长。

### 5.2 插件自己的数据

```
%USERPROFILE%\.dsh\archive-desk\
├── summaries.json                 # 列表摘要缓存（派生数据）
└── trash\
    └── <timestamp>-<random>-<sessionId>\
        ├── meta.json
        └── payload\               # 被移动过来的整个 session-<uuid> 目录
```

`summaries.json`：

```json
{
  "schema": 1,
  "entries": {
    "session-…": {
      "sessionId": "session-…",
      "fingerprint": { "sizeBytes": 45214, "mtimeMs": 1760928000000 },
      "title": "论文提纲",
      "snippet": "把 arxiv 那篇的提纲整理成…",
      "cwd": "D:\\Projects\\TestSpace",
      "createdAt": 1760927000000,
      "updatedAt": 1760928000000
    }
  }
}
```

- 只存列表元数据，**不复制日志**。
- 指纹 = 会话目录总大小 + 目录内最新 mtime；日志变了才重读。
- 删除/恢复/清理引用时失效对应条目；文件损坏或 schema 不兼容时自动重建。
- 原子写，失败只损失一次重建，不影响请求。

`meta.json` 记录条目在两阶段写入中的状态、原始路径与该会话的展示快照。`trashId` 由时间戳、随机后缀与会话 id 组成，避免同毫秒并发碰撞。恢复用 `originalPath`，但必须先校验它落在 `sessions/` 下且 basename 等于 `sessionId`。

### 5.3 状态来源

| 事实                 | 唯一来源                                   |
| -------------------- | ------------------------------------------ |
| 哪些会话被归档       | `ctx.workspaceRegistry.archivedSessionIds` |
| 会话在哪个项目里     | `workspaceRegistry.list()[].sessionIds`    |
| 是否正在运行         | `workspace/session-activity` 瀑布          |
| 是否加载在宿主内存   | `ctx.sessions.get` / `ctx.agents.get`      |
| 标题、摘要、活动时间 | 会话日志（经 `ctx.sessionQuery`，带缓存）  |
| 体积                 | 磁盘                                       |
| 回收站内容           | `trash/*/meta.json` + `payload/`           |

**写操作一律走注册表 API**（`unarchiveSession` / `archiveSession` / `workspace.detachSession` / `workspace.attachSession`），绝不直接改 `workspace.json`。

## 6. 删除与恢复事务

### 6.1 前置校验（逐项）

1. `id` 在 `archivedSessionIds` 里（不在则 `archive/not-archived`）。
2. 查 `workspace/session-activity`：有活动 → 先停（§6.2 第 0 步），停不下来 → `archive/busy`。
   没有活动（包括「加载在内存但从没跑过活」）→ 直接放行。
3. 不在进行中的删除队列里（`inFlight` Set，按 plugin context 共享）。
4. 形如 `session-<uuid>`（防路径注入）。
5. 目录解析结果必须在 `sessions\` 前缀内，且 shard/session 目录都不是 symlink。

任何一项不通过 → 该项 `skipped`，带原因，其余项照常执行。

「已加载」不参与校验：它既不是运行证据，也不是删除障碍，只是删除前要清理的宿主状态。

### 6.2 回收站模式（默认）

```
0. 有活动时 emit('workspace/session-stop', { sessionId })，轮询瀑布直到为空（有上限）
1. 独占创建 trash/<id>/，写 meta.json（phase=moving）
2. rename(会话目录 → trash/<id>/payload)        # 同盘，原子
3. 更新 meta（phase=ready）
4. 删除投影缓存文件（带/不带 session- 前缀都尝试）
5. workspace.detachSession(id)（遍历所有 workspace，尽力而为）
6. workspaceRegistry.unarchiveSession(id)
7. ctx.emit('api-session/removed', id)           # 侧栏立刻消失
```

第 0 步对应用户在归档时看到的「停止活动」：DSH 的 `workspace/session-stop` 会取消该会话的 turn、kill 它的 job、删掉它的定时任务行、取消它的子 Agent，而且是**不保留收件箱**的取消——排队输入不会在之后把会话唤醒。停完再删，宿主内存里即使还留着会话对象，也没有东西会把它写回磁盘。

顺序原则：**先动文件，后动状态**。文件移动失败 = 什么都没变；状态写失败 = 文件已在回收站，归档引用可能残留（`partial`），可在「清理失效引用」里重试。

### 6.3 彻底删除模式

```
0. 同 §6.2 第 0 步：先停活动
1. rm -rf 会话目录
2. 删除投影缓存文件
3. detach / unarchive / emit removed
```

无回收站条目，不可恢复。工具不提供此模式。

### 6.4 恢复（三步事务）

```
1. TrashStore.restore(): 校验 meta/payload/originalPath，rename(payload → 原路径)，
   但保留 trash 条目
2. workspace.attachSession(id)（尽力而为）
   workspaceRegistry.archiveSession(id)（必须成功）
3. TrashStore.discard(trashId) 删除条目
```

- 第 2 步失败 → `rollback()` 把 payload 移回回收站，条目保持 `ready`，返回 `failed`。
- 第 3 步失败 → 会话已恢复且已归档，只留下一个损坏条目，可在回收站里删除。
- 恢复后立即可在「已归档」列表看到；侧栏行要等下一次会话列表刷新（宿主限制）。

### 6.5 失败与回滚

| 失败点            | 处理                                                         |
| ----------------- | ------------------------------------------------------------ |
| meta/独占创建失败 | 中止该项，目录未动                                           |
| rename 失败       | 清理半写条目，报告错误                                       |
| 状态写失败        | 文件已移走，返回 `partial`；归档引用可由「清理失效引用」治理 |
| archive 失败      | 恢复时把 payload 移回回收站，条目保留                        |
| 整批中某项异常    | 不中断整批，逐项返回结果                                     |

批处理串行执行，每项之间让出事件循环。

### 6.6 崩溃恢复

插件激活时扫 `trash/*/meta.json`：

- `phase=moving` 且 `payload` 存在 → 补写成 `ready`
- `phase=moving` 且 `payload` 不存在 → 整个条目清掉
- `ready` 但 `payload` 缺失 → 保留为损坏条目，列表里可删除

## 7. Agent 工具

工具名 `archived_conversations`，一个 `action` 参数，与 UI 共用 Host 服务：

```jsonc
{
  "action": "list | unarchive | delete | restore | trash",
  "ids": ["session-…"], // unarchive / delete 用会话 id，最多 100
  "trashIds": ["…"], // restore 用回收站条目 id，最多 100
  "query": "登录", // list 过滤
  "offset": 0,
  "limit": 20, // list / trash 分页，上限 100
  "confirm": false, // delete 必须 true
}
```

规则：

- `unarchive` 只解除归档：从 `archivedSessionIds` 移出，不动文件、不动 workspace 归属；不存在的目录会跳过。不需要 `confirm`。
- `delete` 必须 `confirm: true` 且 `ids` 非空，单次最多 100 个；超过直接报错，不静默截断。
- 只能删归档集合里的会话；有活动在跑的会先被停止，停不下来则跳过并说明。
- 删除只进回收站，**本工具不提供彻底删除**；`purge` / `empty_trash` 是人工操作。
- 返回结构化摘要：`{ok, deleted, partial, skipped, freedBytes}` / `{ok, unarchived, skipped}`；列表返回精简条目（id/标题/摘要/时间/体积/状态）。
- 结果必须是**无损 JSON**：可选字段条件展开，最后统一 JSON 往返兜底。
- 不接 `tools/pre-execute` 审批闸门：本 profile 的审批策略是 `never`，接了会让工具永久被拒。

工具 schema 必须通过宿主 `assertSupportedJsonSchema`：顶层 `type: 'object'`、`required` 数组、属性级不出现 `required: true`。

## 8. 无配置（刻意）

这个插件**没有** `Config`、`settings.json`、`getSettings/setSettings`，不提供任何部署旋钮。

理由：

- 它是一个用户态管理工具，安全边界应由代码固定，而不是让部署者调。
- 每页条数、排序是页面上的可见控件，默认 20 / 最近活动；不持久化，刷新回默认。
- Agent 永远只能删到回收站；彻底删除只由人在面板里做。这条不做成开关。

代码常量：

| 常量                   | 值     | 用途                     |
| ---------------------- | ------ | ------------------------ |
| `DEFAULT_LIMIT`        | 20     | 列表默认每页             |
| `MAX_LIMIT`            | 100    | 列表/回收站/工具单页上限 |
| `DEFAULT_TRASH_LIMIT`  | 50     | 回收站默认每页           |
| `MAX_MATCHING_IDS`     | 1000   | “全选筛选结果”的 id 上限 |
| `SNIPPET_CHARS`        | 160    | 摘要长度                 |
| `TITLE_FALLBACK_CHARS` | 24     | 无标题时取首条消息前缀   |
| `MAX_IDS`              | 100    | 工具单次批量上限         |
| `MAX_BODY_BYTES`       | 64 KiB | HTTP 请求体上限          |

| `archive/forbidden`        | 该操作对 Agent 关闭 / 审批被拒 |

| `archive/internal`         | 未分类内部错误                 |

## 10. 兼容性、安全与已知限制

### 依赖的内部面

| 依赖                                    | 风险                       | 缓解                                                                           |
| --------------------------------------- | -------------------------- | ------------------------------------------------------------------------------ |
| `sessions\<shard>\session-<id>\` 布局   | 中：升级可能改             | 只按目录名找，不碰文件名；找不到就报 `not-found`，不猜                         |
| `workspace/session-activity`            | 中：事件契约               | 缺失时回退到 Agent `status === 'running'`；无法判定时按「运行中」保守处理      |
| `workspace.json` 存储域                 | 低：用注册表 API，不碰文件 | 只调 `unarchiveSession` / `archiveSession` / `detachSession` / `attachSession` |
| `session_projcache\sessions\<id>.json`  | 低：派生数据               | 带/不带 `session-` 前缀都尝试删除；删不掉也无害                                |
| `sessionQuery.readSession()`            | 中：服务可选               | 未挂载时降级：无摘要、标题用 id；删除不受影响                                  |
| `@deepseek-ai/dsh-client-ui-primitives` | 中：平台 seed 模块         | `dsh.client.external` + 本地类型声明；宿主升级时复核声明                       |
| `api-session/removed` 事件              | 低：事件契约               | 没有它只是需要刷新页面                                                         |

### 安全

- 只允许操作归档集合内的会话 id；路径解析后必须落在 `~/.dsh/sessions/` 内。
- shard 与 session 目录都拒绝 symlink/junction。
- 回收站恢复前校验 `originalPath` 在 sessions root 内，且 basename 等于 sessionId。
- 删除是串行队列，同 id 幂等；trashId 带随机后缀，独占创建。
- HTTP 路由只接受 POST，每个请求先做连接鉴权。
- 可选字段一律条件展开，工具结果做无损 JSON 兜底。

### 已知限制

1. 恢复后侧栏行不会立刻出现（要等会话列表刷新或重启）；管理页里立刻可见。
2. 附件不删：删除会话后 `attachments` 里可能有孤儿文件，这是刻意行为（共享安全）。
3. 只删「归档」会话；未归档的必须先归档。
4. 回收站是全局的（跨项目、跨 profile 的 `~/.dsh`），不跟随项目。
5. 加载在宿主内存里的已归档会话可以直接删：删除前会先停掉它残留的活动（§6.2 第 0 步）。若活动两秒内没停下来，该项被跳过并提示稍后重试——宁可让人再点一次，也不在会话还可能写日志时动目录。
6. 失效引用只能移除引用，不保证能恢复文件。
